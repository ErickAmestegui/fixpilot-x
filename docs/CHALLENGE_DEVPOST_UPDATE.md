## About the project — append this paragraph

The Rescue Challenge lets judges supply the unexpected conditions themselves. Choose either original assembly, set a simulated starting record, and combine missing parts, unavailable tools, recoveries and withdrawn digital reports. The original dependency engine calculates the consequences live: what can proceed, what is blocked, which reports are invalidated, and why. Compare independent alternatives, inspect the 3D state and prerequisite graph, then review the exact changes before applying them to an isolated challenge record. Tool receipts and exportable evidence make the outcome inspectable and reproducible without touching saved user progress.

## Validation / accomplishments

The upgrade passed 219 unit/integration checks and 18 browser scenarios, including preserved Rescue behavior, late part loss, recovery without resurrecting reports, a complete 8/8 digital replay, a second assembly and a separate host approval refusal. An additional 4,608 counterfactual calculations ran through real MCP across all shortage subsets for both assemblies at three simulated progress profiles. These are software and protocol checks, not an LLM benchmark, physical safety certification or independent user study. Exported evidence replayed to the same final inventory and progress in new MCP sessions.

## Product feedback / authentic friction

MCP Apps gave us a standard tool-to-interface contract, but a working card required more than serving HTML: UI capability negotiation, a declared ui:// resource, a self-contained build, the App/AppBridge handshake and explicit host approval. Our local reference host makes those boundaries visible instead of claiming compatibility with untested clients. We also found a race between live previews and comparison display; requiring a validated current preview resolved it. These observations concern our implementation, not reported defects in Alexa+ or Amazon services.
